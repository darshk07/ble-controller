# ble-controller

A desktop app (Electron + React) to control a Magic Lantern Bluetooth LED strip.

## Run the app

```sh
npm install
npm run dev
```

Click **Connect strip**, pick the strip (devices advertising FFF0 get an *LED* tag). Close Magic Lantern on your phone first.

After that the app remembers it: on launch it finds the strip and connects by itself, and reconnects if the strip is
switched off and back on. Click the status pill to give it a nickname, turn auto-connect off, or forget it. The
nickname is stored in the app (`device.json` in Electron's user data folder); the strip's own Bluetooth name can't be
changed because no rename command is known for this protocol.

### Modes

| Mode | What it does |
| --- | --- |
| Color | Color wheel and swatches, with smooth fades between colors. |
| Effects | Rainbow, Breathe, Heartbeat, Candle, Sunset, Ocean, Aurora, Strobe, with a speed control. |
| Screen | Samples your screen 30 times a second and matches its most vivid color, dimming for dark scenes. Optional *React to audio* adds the soundtrack. |
| Music | Listens to system audio (or the mic) and reacts: *Beat* changes color on each beat, *Spectrum* maps bass to warm and highs to cool, *Pulse* breathes your color with the loudness. |

All of these are generated by the app and streamed to the strip as color commands, capped at 25 per second
(`MIN_WRITE_INTERVAL_MS` in `src/main/ble.ts`). Live modes keep running while the window is minimised.
Settings are remembered between launches.

### Permissions

- **macOS**: `npm install` adds Bluetooth, microphone and audio-capture usage descriptions to the dev Electron.app,
  because macOS kills apps that use them without one. Screen mode and system audio need
  *System Settings → Privacy & Security → Screen & System Audio Recording* for your terminal (in dev) or Lantern
  (packaged). System audio needs macOS 14.2 or later; on older versions use *Microphone*.
- **Windows**: system audio and screen capture work without extra permissions.

### Layout

| Path | Runs in | Job |
| --- | --- | --- |
| `src/shared/protocol.ts` | anywhere | Command bytes. |
| `src/shared/color.ts`, `effects.ts`, `analysis.ts` | anywhere | Color math, effects, screen-color and beat detection. Pure TypeScript, reusable on Android. |
| `src/shared/ipc.ts` | anywhere | IPC channel names and types. |
| `src/main/ble.ts` | main | Owns noble: scan, connect, rate-limited latest-wins writes. |
| `src/main/index.ts` | main | Window, IPC, screen/audio capture source selection. |
| `src/preload/index.ts` | preload | Exposes `window.led` to the UI. |
| `src/renderer/src/engine/` | renderer | Capture and the 30 fps light engine. |
| `src/renderer/src/components/` | renderer | React UI. |

## Phase 1: prove the connection

`npm run probe` is the bare Node script used to verify the bytes; it is still handy for testing raw commands.
Needs Node 22+ and Bluetooth turned on. On macOS, grant Bluetooth access to your terminal app when it asks.

```sh
npm install
npm run probe -- scan                         # find the strip, note its name or id
npm run probe -- inspect <device>             # list its services and characteristics
npm run probe -- color <device> ff0000        # should turn the strip red
npm run probe -- brightness <device> 30
npm run probe -- raw <device> "7e 07 05 03 00 ff 00 10 ef"
```

`<device>` can be the id, the MAC address, or part of the name shown by `scan`.
Close the Magic Lantern app on your phone first: most strips accept only one connection.

The command bytes live in `src/shared/protocol.ts`, a plain TypeScript module with no Node imports so the Android app can reuse it.
Color and brightness are verified on the real strip (macOS). Power, mode and speed are not known yet.

### If the bytes don't work

1. Run `inspect` and check that service `fff0` and characteristic `fff3` exist and that `fff3` is writable.
2. Capture what the stock app sends: turn on *Bluetooth HCI snoop log* in Android developer options, use Magic Lantern
   (set a color, change brightness, toggle power), then pull the log with `adb bugreport` and open `btsnoop_hci.log`
   in Wireshark with the filter `btatt.opcode == 0x52 || btatt.opcode == 0x12`. The values written to `fff3` are the commands.
3. Replay a captured command with `npm run probe -- raw <device> "<bytes>"` before adding it to `protocol.ts`.
